## 2. アルゴリズム化可能な人間ヒューリスティクス

プロ耳コピの暗黙知を、実装可能な特徴量・ルールに落とす。

### 2.1 「独立した打鍵/打弦か、部分音か」分類器

| ヒューリスティクス | 特徴量 / ルール | 判定傾向 |
|--------------------|-----------------|----------|
| **同時アタック** | onsetが同フレームで揃うか、時間ずれがあるか | 独立弦：onsetが微妙にズレ／別ピクトランス。部分音：基音onsetと完全同期 |
| **エンベロープ形状** | 部分音のattack/decayが基音と相似か | 相似→倍音。独立→decay・ノイズ成分が別 |
| **ハーモニクス音色** | 高域優勢・基音エネルギー弱い・「鈴/ガラス/キュイーン」 | ナチュラル/ピンチ候補。音量小→`@Re_Mikami`型 |
| **整数比ロック** | f, 2f, 3f…が厳密に揃うか（inharmonicity考慮） | 等間隔縦線→1音の倍音列（`@musicstd`）。不揃い→別ソース or ノイズ |
| **第3倍音＝P5罠** | 3f付近が強いが、独立onsetなし | **弾いてない5度**として捨てる（`@adatinc`） |
| **第5倍音＝M3罠** | 5f付近、特に歪みPC | **メジャー3度の誤検出を抑制**（`@Alice` `@nemurenai` `@nomaxxx`） |
| **融合単音感** | 5度スタック＋高歪みで「1本の太い線」 | パワーコード＝1エンティティ（`@machaaki`）。ボイス数を過大評価しない |
| **開放 vs 押弦** | inharmonicity・高次倍音の豊かさ・ノイズ床 | 開放＝倍音豊か・サスティン長。音色一貫性ペナルティで運指推論（`@19631025`） |
| **ハーモニクス位置事前分布** | 12,7,5,4,3.2,2.7…フレット近傍ノード | ピッチが「そのフレット実音」と不一致ならarm候補（`@LightningGGE` `@SEHA`） |
| **音量階層** | armは相対的に小さい（unless layered） | 弱く澄んだ高音→arm、強く芯がある→実音 |

### 2.2 文脈ベイズ（プロが無意識にやっている事前）

```
P(note is real fretted | audio)
  ∝ likelihood(spectrum, onset, envelope)
  × prior_instrument_knowledge      # ギター知識（どこでarmできるか）
  × prior_genre                     # メタル→pinch/PC多め
  × prior_harmony_progression       # まず進行をざっと（hinatsu）
  × prior_voicing_economy           # 歪み→3度は歌/もう1本に任せる
  × consistency_over_section        # 通して聞く（chitarom）
```

| 文脈ルール | アルゴリズム化 |
|------------|----------------|
| 進行を先に掴む | 粗いchord HMM / Viterbi（`@prentrodgers`もViterbi言及）→細部は局所修正 |
| 全部同時に当てない | multipitch → **最小説明集合**（聞こえた音からコード推測） |
| 脳の補完 vs 実音 | フレーズ全体で再評価；単発ピークは削除候補 |
| ギター2本 | stereo/pan・ダブリング相関でソース分離してからpitch |
| 歪み限界 | gain高→許容同時音数を下げる（PC帯まで） |
| 音程感の薄い低音リフ | F0信頼度を下げ、**リズム+フォーム**を優先（8弦系） |

### 2.3 擬似コード（決定木風）

```
for each spectral peak p at time t:
  if exists fundamental f where p ≈ n*f (n≥2) AND onset(p)≈onset(f):
      label = PARTIAL  # 倍音候補
      if n==3: soft_delete as "ghost fifth"
      if n==5 and distortion_high and power_chord_context:
          soft_delete as "ghost major third"
  elif envelope_glassy and amplitude_low and pitch_matches_harmonic_node:
      label = PLAYED_HARMONIC  # 奏法としてのハーモニクス
  elif independent_onset and string-like noise burst:
      label = REAL_NOTE
  else:
      label = AMBIGUOUS → resolve by:
        progression_prior, stem_isolation, full-phrase consistency
```

### 2.4 プロの「弦の分離感」を実装するなら

1. **Source count prior**：歪みギターは「聞こえるピーク数 ≠ 弾いた弦数」
2. **Timbre clustering**：同一弦の部分音は同じ attack ノイズ指紋を共有
3. **Inharmonicity curve**：フレット実音は弦長依存のinharmonicity；理想倍音列はarm寄り
4. **Playability**：同時に押さえられるフレット集合でスコアリング（TAB逆問題）

### 3.3 パワーコード特有のAI失敗モード（投稿群からの推論）

| 失敗モード | 人間の報告に対応 | 対策（アルゴリズム） |
|------------|------------------|----------------------|
| **Ghost M3** | PCなのにメジャーに聞こえる/検出される | 5fピークを partial 扱い；ジャンルpriorで3rdを落とす |
| **Ghost P5 as second root** | 単音の3倍音を別ノートに | harmonic locking + 共通onset |
| **PCをフルコード化** | Chordify系がC/Am等に振りすぎ | rock/metal prior：5-chordテンプレート優先 |
| **逆に3rdを落としすぎ** | 実際はsus/addや重ねハーモニー | 独立onset・別パン・別ステムなら残す |
| **オクターブダブを別声部** | ダブルトラック/オク下レイヤ | 相関・オクターブ統合 |
| **低音F0喪失** | 8弦・薄音程リフ | multi-F0 + template matching to PC shapes |
| **2本ギターの和音分割不能** | 左右で補完 | stereo source separation first |

## 4. 総括：アルゴリズム設計への「人間の耳の仕様書」

```
┌─────────────────────────────────────────────────────────┐
│  Layer 0: Stem / stereo separation（人間の「分離して聴く」） │
│  Layer 1: Onset-synced harmonic sieve（アタック同期で倍音刈り）│
│  Layer 2: Distortion-aware voice budget（歪み→同時音数を削る） │
│  Layer 3: PC template + M3/P5 ghost suppression             │
│  Layer 4: Progression HMM / Viterbi（文脈で確定）            │
│  Layer 5: Playability + harmonic-node prior（運指・arm）      │
│  Layer 6: Human listen loop（「機械は最終判断できない」）      │
└─────────────────────────────────────────────────────────┘
```

**人間のコア洞察（今回の検索で最もアルゴリズム向き）**

1. **第3倍音＝P5、第5倍音＝M3は「弾いてないのに聞こえる」** → multipitchの最大の敵  
2. **歪みPCは和音ではなく太い単音として知覚** → ボイス数モデルを変える  
3. **onset非共有・音色非相似・パン差**だけが「本当の別弦/別音」  
4. **ハーモニクスは音量・キラキラ・ノード位置・実音との音高不一致**で分離  
5. **開放/押弦の倍音差**は運指推論の特徴量  
6. **文脈（進行・ジャンル・楽器知識）なしのピーク列挙はプロもやらない**  
7. **AIコード解析は「粗い地図」、最終は耳＋試奏**（X上の実務コンセンサス）
