# 論文精読ノート: 和音復元・エンジン妥当性 (grok調査の追跡読解)

日付: 2026-07-26 / 方法: grok X調査(10周+20周)が挙げた論文をWebFetchで直接読解

## MuScriptor (HF papers 2607.08168, GitHub muscriptor/muscriptor)

- デコーダオンリーTransformer 60M〜1.4B。入力=5秒メル(16kHz/512bin)+楽器リスト。
  CFG α=2。合成145万MIDI+実17万曲(1.1万h)+RL後訓練300曲。
- 実測: Onset F1 60.4 / Offset 49.0 (372曲)。**同一ピッチ×同一楽器の同時重複音は
  「短い方を削除」して評価**(込みだと51.8) = **和音の重複はむしろ弱点**。
- ギター/歪み特化評価なし。velocity出力なし。5秒チャンク固定。
- 入手: pip install muscriptor / HF gated (無料承認) / small=CPU可 / MPS対応。
- **ライセンス: コードMIT・重みCC BY-NC 4.0(非商用)** → 製品組込み不可。
  評価・比較用途のみ(#146)。
- 結論: 「MT3後継の万能エンジン」という期待値は下げるべき。ただし検出候補の
  アンサンブル素材としての3ベンチ実測は価値あり(#146継続)。

## 逆倍音クラスタリング/OT (Björkman & Elvander, arXiv:2508.02471)

- コスト c(ω,ω0)=min_k(ω/ω0−k)^2 で周波数を最近傍倍音へ輸送。ω0^2正規化で
  低f0バイアスを除去。サブオクターブ誤りへの明示的対処が設計動機。
- 倍音共有(5度3:2/オクターブ2:1)は不等式制約+スパース正則化ηで解くが、
  「単純比のf0分離はηの慎重な調整が必要」と自認。
- 反復解法(Sinkhorn系・離散化グリッド・デバイアス再解)。コード公開記載なし。
- 結論: 我々の「非重複倍音の直接プローブ」はこの問題の軽量特化版として妥当。
  OT全体導入は依存・計算コスト大でR&D保留が正しい。

## TART (arXiv:2510.02597)

- 4段: ピアノモデルのギター適応→MLP奏法分類→Transformer弦フレット割当→LSTM TAB生成。
- 和音の扱いは抄録から不明。奏法(スライド/ベンド)注釈が売り。
- 結論: 奏法認識の将来参考。和音復元への直接知見なし。

## Fretiq (arXiv:2607.18303)

- 26次元スペクトル特徴(MFCC13が主役)で弦分類。フレーム97.1%/実運用87.8%。
- **単音限定**(single-instrument, single-player preliminary)。和音不可。
- 結論: 単音の弦推定には使えるが縦積み問題には未対応。運指DPの補助候補まで。

## Fretting-Transformer (arXiv:2506.14223)

- T5でMIDI→TAB。弦フレット曖昧性+演奏可能性。DadaGP/GuitarToday/Leducで訓練。
  A*・Guitar Proと比較。
- 結論: 我々の運指DP(#142較正済み・織田哲郎実運指68/99一致)の代替候補だが、
  現行DPで用が足りている間は導入コスト過大。

## Slot-Attention MI-MPE (arXiv:2606.01460)

- CQT→順不同のソース別ピッチマップ集合(Hungarian matching)。URMPで楽器族分解は
  改善するが**stemレベルのソース割当は未解決**と自認。
- 結論: 研究段階。多楽器分離の将来参考。

## HARP (arXiv:2607.16657)

- ニューラルコーデックの残差分配の話(Interspeech 2026)。AMT向けではない。
- 結論: 対象外(grokの文脈では倍音構造の扱いの参考例まで)。

## 総合判断 (2026-07-26時点)

1. 現行路線(Basic Pitch + 物理証拠スタック + GT較正)は研究水準に照らして妥当。
   「倍音共有音の分離は最新研究でも未解決の難所」が客観的事実。
2. 次の実装候補は (a) MuScriptorアンサンブル実測(#146・非商用制約付き)
   (b) 曲内コード語彙事前分布 (c) 同時オンセット群化(ストローク単位の和音判定)。
3. fine-tune以外で検出器自体を替える決定打は現時点で存在しない。
