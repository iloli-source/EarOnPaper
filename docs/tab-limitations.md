# なぜ「完璧なTAB譜」は今の技術では作れないのか

作成: 2026-07-27 / 根拠: 本プロジェクトの実測データ(#144/#146/#147/#148/#149)と公開研究の精読

**結論を先に**: 「TAB譜が作れない」のではない。和音入りのTAB譜は既に出力できている（下記の到達点）。作れないのは「**プロの採譜者が手で書いたものと同じ完成度**」であり、それは工夫不足ではなく、以下の4つの壁——うち2つは物理法則そのもの——による。

## 現在の到達点 (2026-07-27)

| 指標 | 値 |
|---|---|
| 課題曲「夢見る」の和音縦積み再現率 | 25/27和音 (92.6%) |
| プロ録音ベンチ(GuitarSet10曲)の音符一致F1 | 0.690 |
| 同・和音縦積み再現率 | 77.9% |

つまり「約2割の和音が単音に化け、実際より多めの音が混ざる」水準。ここから先が進まない理由が本書の主題。

## 壁1: 物理の縮退 — 「弾いた音」と「倍音」の周波数が完全に一致する

ギターで低い弦を鳴らすと、弦は基音と同時に**整数倍の倍音**を必ず鳴らす。ギターの和音で最も使われる音程——オクターブ(+12半音)とオクターブ+5度(+19半音)——は、下の音の第2・第3倍音と**周波数が完全に重なる**。整数倍の関係のため「重ならない部分音」が数学的に存在せず、スペクトルをどれだけ精密に分析しても、上の音が「弾かれた実音」か「下の音の倍音」かを完全には区別できない。

実測（分離を試みてすべて失敗した記録）:
- 偶数/奇数倍音比: 実音 med 0.93 vs 幽霊 med 0.73 — 分布が重なり分離不能 (#144, 501音ラベル付け)
- 倍音包絡からの突出度(平滑性超過): 実音 med 2.16 vs 余剰 med 2.01 — ほぼ同一分布 (#147, 441音)

## 壁2: 「余計な音」は音響的には実音 — 削る手段が存在しない

検出しすぎた音を後から削る「剪定」を3経路すべて実測検証し、**全て負の結果**で確定 (#147):

| 経路 | 結果 |
|---|---|
| (a) 検出確信度でカット | 弱い分離のみ。実走A/Bで縦積み再現率が退行(0.779→0.757)し逆効果 |
| (b) 和音単位の倍音整合 | 分布ほぼ同一で分離不能。そもそも倍音で説明できる余剰は全体の24%のみ |
| (c) 整列(採点方法)の見直し | 余剰の74%は時間許容を緩めても余剰のまま。採点は公正 |
| 補: コード文脈(#149) | 余剰の方がコード整合的(文脈外率: 正解14.3% > 余剰11.5%)で文脈ゲート無効 |

余剰音の実体は「共鳴・弦の再発音など、**物理的には実際に鳴っている音**」。マイク1本の録音からこれを人間の意図（「これは弾いた音、これは鳴ってしまった音」）で仕分けする情報は音響信号に残っていない。

## 壁3: TAB固有の不定性 — どの弦で弾いたかは音に残らない

同じ音高はギターの複数の弦×フレットで出せる（例: 2弦8フレットと3弦12フレットは同じ音）。**どの弦で弾いたかを示す物理情報は音に含まれない**ため、TAB譜の核心である弦・フレット割り当ては音源からは原理的に一意に決まらない。人間のTAB職人は運指の自然さ・前後の文脈・演奏慣習で決めており、機械は規則で近似するしかない。

（弦ごとに独立録音するヘキサフォニックピックアップがあれば解けるが、一般の音源・YouTube動画には存在しない。本プロジェクトでは検証用データ(GuitarSet)としてのみ利用。）

## 壁4: 世界最高峰も同じ壁の前にいる

- 最新の公開採譜モデル **MuScriptor**（Kyutai/Mirelo, 2026-07公開, 17万曲で学習）でもギターのOnset F1は **60.4**。しかも**同時に重なる同音を評価から除外**した数字で、含めると51.8に落ちる。＝和音の縦積みは業界全体の共通弱点 (#146精読)
- 商用サービス（Klangio等）にも和音の取りこぼし・幽霊音の不満報告が多数（X調査30周: docs/research/grok10-tab-chord, grok20-deep）
- 音源分離の最新モデル(Mel-RoFormerギター特化)も既存構成に勝てず (#148・A/B実測)
- SongsterrやUltimate Guitarの「綺麗なTAB」は**人間の手書き**であり、AI出力ではない

## 壁を越えるとしたら何が必要か（と、その現状）

| 手段 | 現状 |
|---|---|
| 大量の正解付きギター録音での検出器の追加学習 | GPU・クラウド費用が必要のため見送り（費用制約） |
| 弦別録音(ヘキサフォニック)を入力にする | 一般ユーザーの音源では入手不能 |
| 人間の後編集を前提とした「たたき台TAB」+編集UI | **現実的な路線**（#121/#125 楽譜エディタ構想） |

## 結論

現行エンジンは無料・ローカル・公開技術の制約下で、公開されている世界水準と同等以上に到達している。しかし「倍音と実音の物理的縮退」（壁1・2）と「弦割り当ての原理的不定性」（壁3）は信号処理の工夫では越えられず、最新の学習ベースモデルでも同じ壁に当たっている（壁4）。

したがって現実的な目標設定は「**縦積み9割超のたたき台TABを自動生成し、残りを人間が仕上げられる形にする**」であり、「プロの手書きTABと同一の完成度を全自動で」は現在の技術水準では達成不能——これが本プロジェクトの実測に基づく正直な結論である。
